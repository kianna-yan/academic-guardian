# 学业护航 · Academic Guardian

> 面向高校的**学业预警智能体**。以学生端为主视角，同时覆盖辅导员、教务、家长三个协同角色。

![状态](https://img.shields.io/badge/状态-开发中-blue)
![技术栈](https://img.shields.io/badge/FastAPI%20%2B%20Vue%203%20%2B%20BM25-informational)
![许可](https://img.shields.io/badge/license-MIT-green)

**核心主张：把"期末数挂科"变成"期中看见风险，并且知道该做什么"。**

现有高校的学业预警基本是结果性统计——学期末统计不及格学分，超线就发告知函、通知家长。此时学生已经挂了一学期，干预窗口早已关闭。本项目用过程性数据（出勤、作业、期中、平台行为）提前 8–10 周识别风险，并把"为什么"和"怎么办"一并给出。

## 核心能力

- **六维加权风险评分**：学业成绩、课程难度、出勤、作业完成、期中表现、平台活跃度六项加权，权重与阈值全部配置化，**任意一分的来源可手工复算**
- **可解释归因**：不只给总分，还给每项的贡献分与扣分理由——学生能看清是哪门课、哪个环节把自己推进风险区
- **数值不经模型**：挂科、学分缺口等确定性条件走硬规则，六项分数由本地函数计算；模型只负责组织语言，**模型不可用时风险评分、归因与行动清单仍完整可用**
- **一校一规检索**：BM25 中文二元切分索引校内学业管理规定，回答必须带条款出处，拒绝无源引用
- **四端协同**：学生端自助诊断、辅导员端批量锁定重点对象、教务端院系概览、家长端沟通话术
- **四类文书生成**：预警告知、家校沟通、学习计划、整改跟踪，全部由结构化结果驱动，不由模型自由发挥

## 技术栈

| 层 | 选型 |
| --- | --- |
| 前端 | Vue 3 + Vite，图表以原生 SVG 手绘（无重型图表库） |
| 服务 | Python 3 + FastAPI，SSE 流式响应 |
| 检索 | BM25 + 中文二元切分，条款级引用 |

| 数据 | 用户导入的 CSV / 粘贴文本，本地处理，无持久化存储 |

## 一、要解决的问题

| | 现有做法 | 本项目 |
| --- | --- | --- |
| 时点 | 学期末，出成绩之后 | 第 8 教学周，期中之后 |
| 依据 | 不及格学分是否超线 | 六维过程性数据加权 + 硬规则 |
| 输出 | 一张告知函 | 风险等级 + 归因拆解 + 编号行动清单 |
| 干预窗口 | 已关闭 | 还有 8–10 周 |

**这不是"预警得不准"的问题，而是"预警得太晚、且只告诉结果不告诉原因"的问题。** 而这个问题的解法必须同时具备三件事：多维度数值计算（规则引擎擅长）、非结构化校规检索（关键词搜索做不好）、个性化语言生成（模板写不出来）——只有把三者串起来的 AI 系统能做成。

## 二、四个端各做什么

| 角色 | 核心价值 | 主要功能 |
| --- | --- | --- |
| **学生端（主）** | 自查 + 补救 | 风险分与等级、六因素归因、课程级挂科概率、编号行动清单、可追问的对话助手 |
| **辅导员端** | 减负 + 闭环 | 按风险排序的名单、筛选、学生画像、一键生成谈话要点、干预记录留痕、班级周报 |
| **教务端** | 规则 + 全局 | 风险分布看板、班级对比、预警阈值在线配置并实时重算、预警名单导出 CSV |
| **家长端** | 沟通 + 合力 | 学生状态通俗解读、学校已做的帮扶、家长配合建议、家长信生成 |

四端共用同一套评分引擎与知识库，只是视图和话术不同。

## 三、为什么必须是 AI 原生

| 环节 | 传统做法 | 本项目的做法 | 去掉 AI 会怎样 |
| --- | --- | --- | --- |
| 风险归因 | 超线即预警，只报数字 | 六因素加权拆解，每项贡献可复算 | 学生知道"62 分"，不知道"该补出勤还是补作业" |
| 校规匹配 | 关键词全文搜索 | BM25 语义相关性排序，回答下方附条款出处 | "我 15 学分挂科算不算降级"这类问题搜不到 |
| 行动建议 | 固定模板填空 | 按个人六因素短板生成编号清单 | 输出千篇一律，学生不会执行 |
| 文书生成 | 辅导员手写 | 谈话要点 / 家长信 / 周报按学生实际数据生成 | 一个人一天写不完 240 份 |

**关键的工程立场：所有数字由工具函数计算并返回，大模型只负责组织语言。**

成绩和预警是敏感数据，模型编一个分数就是事故。因此 Agent 层采用"意图识别 → 工具调用 → 事实拼装 → 语言润色"四段式，模型永远拿不到计算权。没有配置 API Key 时，系统用模板拼装同样能完整运行——**这不是降级方案，而是把"可信"放在"智能"之前的设计选择**。

## 五、风险模型

```
风险分 = Σ (权重ᵢ × 因素ᵢ归一化值) × 100     再叠加硬性规则
```

| 因素 | 权重 | 数据来源 |
| --- | --- | --- |
| 课堂出勤 | 26% | 考勤记录 |
| 作业提交 | 20% | 作业平台 |
| 期中成绩 | 20% | 教务成绩（含班级 z-score） |
| 学习投入 | 12% | 平台登录、视频完成率、最近活跃 |
| 历史欠账 | 12% | 上学期 GPA、累计不及格学分 |
| 学分进度 | 10% | 已修学分 vs 培养方案 |

**权重依据：** 【待补——写明依据来源，例如：参考《普通高等学校学生管理规定》与学工文献的预警指标研究，结合 3 位一线辅导员访谈赋权；权重在 `engine/risk.py` 中集中配置，可按校调整】

硬性规则（不允许被加权平均稀释）：

- 期中不及格 ≥ 2 门 → 直接进入红色
- 缺勤率 ≥ 25% → 至少黄色 + 15 分
- 累计不及格学分 ≥ 25 → 至少 80 分

**可解释性：** 每个因素的 `权重 × 归一化值 × 100` 就是它贡献的分数，六项相加等于风险分。学生看到的"出勤 20.2 分、作业 17.5 分"不是形容词，是可复算的加数。

## 六、RAG 与"一校一规"

`knowledge/` 下 6 份文档、24 个条款，覆盖华南理工、北京科技大学、上海理工、深圳技术大学、上海海事大学与教育部政策。检索用 BM25（中文按字二元切分），返回结果带学校与条款标题，直接呈现在回答下方作为引用。

换一所学校只需新增一个 md 文件——"一校一规"是本项目相对通用产品的差异点：华南理工是 15 学分预警、25 学分降级，北京科技大学是单学期不足 14 学分警示，深圳技术大学是学分不足所选二分之一，规则完全不同。**通用的"学业预警"产品在这里会直接失效，因为判定标准由每所学校自己定。**

> 引用条款仅用于演示检索与解答能力，不作为任何实际处分依据。正式使用须以各校现行有效文件为准。

## 七、核心功能范围

**本期实现：** 四端视图 · 六维风险评分与归因 · 课程级挂科概率 · 校规 RAG 问答（带条款引用）· 编号行动清单 · 四类文书生成 · 阈值在线配置与实时重算 · CSV 导出

**本期明确不做：** 对接真实教务系统、学生身份认证与权限体系、移动端 App、消息推送、消费/门禁/社交等非教学数据接入。

## 八、运行

```bash
cd academic_guardian
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
python -m uvicorn app:app --port 8600
```

打开 <http://127.0.0.1:8600> ，用 URL 可直接进入指定端：

- `/#student` 学生端
- `/#counselor` 辅导员端
- `/#admin` 教务端
- `/#parent` 家长端

### 接入大模型（可选）

复制 `.env.example` 为 `.env` 并填写，支持任意 OpenAI 兼容接口（DeepSeek、通义、Kimi、vLLM）：

```
LLM_API_KEY=sk-xxx
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

启动时读取环境变量（Windows 可用 `set LLM_API_KEY=...` 后再启动）。接入后，对话回答与文书措辞由模型改写，但事实字段仍由工具提供；未接入时侧边栏会显示"规则引擎模式"。

## 十、数据说明与合规

当前使用**确定性生成的模拟数据**（固定随机种子，每次启动一致）：240 名学生、6 个班、6 门课、第 8 教学周，含上学期 GPA 与挂科记录。

这样做的原因：真实学情数据受《个人信息保护法》与校级数据管理规定限制，比赛阶段无法获取，也不应获取。数据层是独立的 `data.py`，接口形态按真实教务系统字段设计，替换为真实数据源时上层的评分、RAG、文书逻辑不需要改动。

**风险分布现状：** 红色 15 人（6.2%）、黄色 46 人（19.2%）、正常 179 人（74.6%）。【待补——如要与某高校公开比例对比，须给出可查来源；无来源则删除对比，只保留"分布符合预期梯度"的定性描述】

## 十一、边界与后续

明确不做的事：

- **系统不作出任何处分决定。** 预警只是提醒，所有升级、降级、退学均需人工核实与学校程序。
- **不做行为监控的无限扩张。** 当前只用教学相关数据（考勤、作业、成绩、平台学习行为），未引入消费、门禁、社交等数据。
- **保留申诉入口。** 数据错误可提交复核（接口已预留，前端待补）。

后续可做：接入真实教务系统 API、预警结果的申诉与复核流程、按专业/课程维度的群体归因、把访谈记录纳入模型形成"干预有效性"反馈闭环。
