# 20261112 消息弹窗改为「一次登录只播一次」

## 一、任务

进端口时右上角弹出的三条提醒（学业黄色关注 / 作业未交 / 考勤旷课），原来**每回一次门户就重播一遍**，
叉掉也没用。要求：刚登录时出现一次，叉掉之后本次登录的这个端不再出现。

## 二、约束

- 不能把提醒彻底删掉：铃铛红点、消息中心里的未读列表要照旧，只是不再"弹脸"。
- 上一轮刚做的"进板块隐藏、回门户再现"必须保留（板块页里卡片会压住表格和图）。
- 换账号 / 重新登录必须能重新报到，否则下一个人看不到自己的提醒。

## 三、AI 给了什么

1. 进端口报到（`popPortNotices`）加账号级守卫：`reportedAccount` 记一次，之后就 return，
   不再依赖"只要未读就再报一遍"的旧逻辑。
2. 叉掉时把通知 id 记进 `dismissedKeys`，`pushNotice` 里先查这张表——
   轮询回调（`onArrive`）若把同一条又送进来，会被直接拦掉，不会"关了又弹"。
3. 两个记号都写进 `sessionStorage`（`ag.notice.reported.<账号>`、`ag.notice.dismissed`），
   同一标签页刷新页面也不重播；退出登录时连同清空。

## 四、人工判断

- **第一版只做内存记法，测试第 ⑥ 项（刷新不重播）直接 FAIL。** 原因是 `auth.profile` 是异步
  hydrate 的：刷新时那个 watch 先以 `undefined` 触发一次，被当成"退出登录"，把 sessionStorage
  里的报到记号清掉了，随后 profile 到齐又重新报到一遍。加了个 `hadProfile` 守卫——
  只有"登录过之后再掉成空"才算退出，启动时的空 profile 不动。这条如果只看代码很难发现，
  必须真的刷新一次才暴露。
- **没有改成"标已读就不弹"。** 已读是服务端状态，影响铃铛红点；本次需求只是"别反复弹"，
  动已读会让学生以为消息被系统吞了。二者分开，红点始终保留。
- **sessionStorage 而非 localStorage。** localStorage 会跨标签页、跨天残留，
  关掉浏览器明天进来就再也不报了；sessionStorage 的边界正好是"这次登录的这个标签页"。

## 五、验证

`web/scripts/verify-notice-once.mjs`（真实点击门户节点）：

① 首次进场 3 条 → ② 叉掉后 0 条 → ③ 进板块 0 条 → ④ 返回门户 0 条 →
⑤ 反复进出 2 轮仍 0 条 → ⑥ 刷新页面 0 条 → ⑦ 清掉会话记号（模拟重新登录）3 条 → 无 JS 报错。

8 项全部 PASS，返回门户后的截图确认铃铛红点仍是 3。
