# 第四轮体验修复（四项）：层级、编号、异议跳转、消息弹窗范围

日期：2026-11-12 ｜ 基线：`学业预警智能体_源码_20261112_版式定稿`

## 1. 任务

在版式定稿版本上收到四条反馈：

1. 辅导员端「风险名单」里点开学生抽屉、再点「生成告知函」，文书弹窗被抽屉压住一半，正文读不全。
2. 学生端「学情总览」页面上两个区域标带显示 `01 学业总览` / `03 风险归因与行动`，编号跳号。
3. 学生端「考勤与作业」里每条记录右侧的「异议」点了没反应。
4. 右上角那列进端口报到卡片（学业黄色关注 / 作业提醒 / 考勤提醒）在进入板块页后仍然挂着，挡住表格与图表。

## 2. 约束

- 只改交互与层级，不动版式、配色与任何数据口径。
- 四个问题分别落在「组件层」「视图层」「应用层」，补丁要打在正确的层上，不能为一个端的心智去改公共组件的外观。
- 门户首屏的「进门报到」是既定交互，不能因为第 4 条被误删。
- 路由跳转不得破坏 `sharecode` 与登录守卫（线上靠分享码放行）。

## 3. AI 给了什么 / 人工判断

**① 告知函层级。** 第一反应是「弹窗没 `append-to-body`」，实测并非如此：`el-dialog` 默认就挂到 body，问题在于抽屉先开、Element Plus 的层级计数器把更高的 z-index 分给了抽屉（实测遮罩 2004）。采纳的方案是给这个弹窗的遮罩单独挂 `modal-class="letter-modal"`，再用一条全局样式把它提到 3200（必须 `!important`，因为遮罩的 z-index 是内联样式）。**人工判断：不选「打开告知函就关掉抽屉」这条更省事的路**——关掉抽屉会丢掉学生上下文，看完函还得重新点回名单。

**② 编号跳号。** 编号原本按「学情总览 → 成绩走势 → 风险归因 → 考勤 → 复核」整条链路编排，改成独立页面后，总览页只承载 01 和 03，中间的 02 落在另一个页面上。按反馈把总览页的第二块改为 `02`。**人工判断：只动总览这一处**，成绩走势页仍是 02——两页各自从头计数，比在页内留一个空号更符合阅读习惯。

**③ 异议按钮。** 原实现是在当前页 `scrollIntoView('.appeal-form')`，但那个表单只在 `sec === 'appeal'` 时渲染，在考勤页根本不存在，所以「点了没反应」。改成：预填记录（类型 / 课程 / 记录号）→ `router.push('/student/appeal')` → 延时 420ms 再滚动到表单。**人工判断：延时是必要的**，路由 `afterEach` 会把内页滚回顶部，早滚会被那次复位盖掉。

**④ 消息弹窗范围。** 弹窗挂在 App 层，进板块后栈里的条目还在。改法是在 `pushNotice` 里加 `route.meta.home` 守卫，并在路由切换时把非首屏的栈清空，模板上再 `v-if="isHome"`。**人工判断：清空而不是仅隐藏**——回门户时要重新「报到」一次（`popPortNotices` 不看弹过没弹过），留着旧栈反而会出现「进去前的消息」和「这次进门的新消息」混在一起。

## 4. 验收

`web/scripts/verify-round6.mjs`：真浏览器、真点击（门户节点 → 板块 → 返回门户），10 项断言全 PASS，含

- 告知函遮罩 z-index 3200、`elementFromPoint` 命中的是文书而不是抽屉；
- 学情总览标带 `01 / 02`；
- 异议跳转后 URL 为 `/student/appeal` 且表单带着「针对：考勤记录 · 计算机组成原理（…-2026-10-15-1-2 节）」；
- 板块页无 `.ntf-stack`，回门户后 3 条重新出现。
