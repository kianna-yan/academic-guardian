## 一、把平台导出的源码拆成 8 条提交

**任务**：从开发平台导出的是一个 zip（76 个文件、解压 2.6MB），需要按赛制要求"细粒度提交"入库，且不能伪造历史。

**约束**：

- 必须能一条命令跑起来（评审复现成本要低）
- 前端构建产物要不要入库，需要判断

**AI 给了什么**：

按模块边界切 8 条提交——工程配置 / 风险引擎与数据层 / 检索与 Agent 与文书 / FastAPI 服务 / Vue 前端 / 构建产物与旧版回退 / README 修正。三条建议被采纳：

1. 提交信息写长描述（动机 + 改了什么 + 怎么验证），不只写一行标题
2. 新增 `.gitattributes`（`* text=auto eol=lf`）统一行尾，避免 Windows 检出后 CRLF 混进仓库
3. `web/site/` 构建产物**要入库**——否则 `app.py` 找不到构建产物会回退到 `static/` 的旧版原生前端，评审看到的就不是 Vue 版

**人工判断**：

- 拒绝了"倒填提交时间"的建议。宁可承认这是一次性生成的原型基线，也不能伪造过程——被判造假比"历史短"严重得多
- 拒绝了把 `static/` 删掉。它虽然被取代，但 `app.py` 里保留着回退路径，删了代码就跑不通，留着并在 README 注明"仅作回退路径"

## 二、git clone 报证书错误的排查

**现象**：`git clone` 报 `schannel: next InitializeSecurityContext failed: CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`。

**排查路径（四步，前两步都是无效尝试）**：

1. `git -c http.schannelCheckRevoke=false clone` —— 仍报同样的错
2. 换 TLS 后端：`http.sslBackend=openssl` —— 错误变成 `unable to get local issuer certificate`
3. 检查 git 自带的 `ca-bundle.crt`：里面有 DigiCert Global Root G2（GitHub 的根证书），**说明不是缺证书，是证书链被换掉了**
4. 导出 Windows 根证书存储（540 张）检查：发现 `Sangfor Technologies Inc.`（深信服）——网络里有设备在做 HTTPS 解密

**根因**：拦截设备用自己签发的证书替换了 GitHub 的真实证书。Windows 信任这张证书（所以能连上），但查不了吊销状态（第一个报错）；git 自带的证书包里没有它（第二个报错）。

**结论与取舍**：合并 Windows 根证书 + git 证书包后仍然验不过，说明拦截方的中间证书不在根存储里。最后用 `http.sslVerify=false` 放行。

**这是一次明确的妥协，不是最佳实践**：关掉校验意味着无法防范中间人。当前接受它，是因为这台机器只在校园网内使用、且仓库是公开作品。换到干净网络应执行 `git config --global --unset http.sslVerify` 恢复校验。**技术文档的"部署与安全"一节要如实写这一条，不能假装没发生。**

## 三、发现的文档与实现不符（已修）

拿到源码后对照 README，发现三处描述与代码矛盾：

| 位置 | 原描述 | 实际实现 |
| --- | --- | --- |
| 技术栈表 | Vue 3 + Vite，图表以原生 SVG 手绘（无重型图表库） | Vue 3 + **TypeScript** + Vite + Element Plus + **ECharts** |
| 架构图 / 选型说明 | 前端用 Vue 3 CDN 版，静态 HTML + ES Module，不引入 npm 构建链 | Vite 工程化构建，产物输出到 `web/site/` |
| 数据行 | 用户导入的 CSV / 粘贴文本 | 240 名学生模拟数据（固定种子） |

**教训：文档是照着"设计时以为的样子"写的，代码改过之后没人回头同步。** 评审照着文档去跑、去对照，第一处不符就会让他们怀疑整份材料的可信度。以后每次合并功能，先改文档再提交。
