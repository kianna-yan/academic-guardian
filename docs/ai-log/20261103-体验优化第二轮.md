# 2026-11-03 · 体验优化第二轮（七项）

## 任务
用户在使用线上版本后又提出七个问题：
1. 某些窗口首次进入划不动，要切到其他页再回来才能滚动
2. 家长端「家校沟通」排版不合理（输入框虚高、底部黑色溢出）
3. 辅导员端希望能直接选学生家长发起家校沟通，或在学生详情里一键跳到对应家校沟通窗口
4. 家校沟通窗口要显示对方联系方式（家长端看辅导员电话，导员端看家长电话）
5. 通知弹窗每次弹两个（同一封家校消息弹「发来一条消息」+「发来家校消息」）
6. 辅导员端加「智慧森林」：每个学生一棵树，每个班一片森林
7. 教师端排版冗杂，所教各班级要分开；侧栏新增「历年真题 / 网课资源」上传入口

## 约束
- 五端共用同一套侧栏与路由结构，新增入口必须按现有 NavGroup 约定写
- 后端演示场景为单进程内存态，文件上传要支持「线上只读挂载时退化成内存态」
- 联系方式字段不能凭空编造：辅导员无真实电话，用占位号 `138-0013-8000`；家长电话按学号尾四位生成占位号
- 树形可视化用纯 SVG，不引入新图表库

## AI 给了什么 / 我们改了什么

### 滚动 bug（任务 1）
- **根因**：`.view.view-chat { overflow: hidden }` 与 `.view { overflow-y: auto }` 切换时浏览器不立即重排，首次进入某些页面滚动状态不刷新
- **改法**：router afterEach 用双层 `requestAnimationFrame` 等组件挂载完毕，并强制 `void view.offsetHeight` 触发一次 reflow；main.css 给 `.view` 加 `scroll-behavior: smooth`
- **验证**：scrollTop=297, scrollHeight=24185, canScroll=true（之前会被锁在 0）

### 家长端家校沟通排版（任务 2）
- **根因**：`.msg-page` 用 `min-height: calc(100vh - 120px)`，但外层 `.view` 已是 overflow-y:auto，min-height 让内容溢出 .view 触发外层滚动，输入框虚高、底部黑色溢出
- **改法**：`.msg-page` 改成 `height: calc(100vh - 96px); display: flex; flex-direction: column`，msg-layout flex:1 min-height:0 让内部 conv-body 自己滚动；去掉冗余 `<h2>` 大标题（顶栏已有）；输入框 rows=2 + 按钮 align-self:stretch 同高对齐
- **顺带**：发现顶栏副标题与 MessageView 内提示文字重复，把 MessageView 内的提示改成简短引导句

### 辅导员端发起家校沟通（任务 3）
- **两种入口**：① StudentDrawer 学生详情抽屉里加「家校沟通 →」按钮，点击 `router.push({ path: "/messages", query: { sid } })`；② MessageView 导员端会话列表上方加搜索框，按姓名/学号过滤
- **query.sid 自动选中**：MessageView onMounted 与 watch route.query.sid 都会查找匹配的 thread 并 activeThread 选中

### 对方联系方式（任务 4）
- **后端**：`engine/notifications.py` 的 `threads_for` 给每条 thread 加 `peer_phone` 字段
  - 家长端：peer_phone = 辅导员电话（占位 `138-0013-8000`，数据集里没有真实辅导员电话）
  - 导员端：peer_phone = 家长电话（按学号尾四位生成 `138-0013-{tail}`）
- **前端**：types.ts 的 MessageThread 加 `peer_phone?`；MessageView 在 conv-peer 行加 ☎ 图标 + `<a href="tel:">` 拨打链接
- **验证**：curl 直接拉 messages 接口返回 `peer_phone: "138-0013-8000"`

### 通知去重（任务 5）
- **根因**：同一封家校消息走两条路径触发弹窗
  - 后端 `MESSAGES.send` 通过 `NOTIFS.push(..., "message", "{name} 发来一条消息")` 推一条
  - 前端 `notices.ts refreshMessages` 检测到新消息后又通过 `listeners.forEach(fn([合成 notice]))` 推一份 `id=msg-${m.id}, title={name} 发来家校消息`
- **改法**：后端 `NOTIFS.push` 的 kind 改为 `family_message`、title 统一为「{name} 发来家校消息」；前端 `refreshMessages` 删掉那段 listeners 推送，让后端推的那一份负责弹
- **验证**：家长发消息后导员端只弹一个窗，title=`汪永康 家长 发来家校消息`

### 智慧森林（任务 6）
- **新组件** `CounselorForest.vue`：接收 RosterRow[]，按 class_name 分组，每个班一片森林卡片；学生按风险等级排序（红→黄→绿）
- **树形 SVG**（60×80 viewBox）：
  - green：茂盛圆冠深绿 + 浅绿点缀
  - yellow：椭圆黄冠 + 几片飘落叶子
  - red：稀疏枯枝 + 红色警示果
- **班级统计**：每片森林头部显示绿/黄/红人数 + 健康度百分比
- **入口**：modules.ts counselor 分组 work 项加 `{ key: "forest", label: "智慧森林", to: "/counselor#forest" }`；CounselorView 在风险名单后嵌入 `<RegionBand id="forest" no="02" tone="learn">` + `<CounselorForest :rows="rows" />`
- **验证**：6 个班级森林卡片，240 棵树（195绿/37黄/8红），hash=#forest 滚动到位

### 教师端分班 + 真题/网课上传（任务 7）
- **班级分开排版**：TeacherView 新增 `classFilter` state + `classGroups` computed（按班级分组统计）；在 StatGrid 后加「所教班级」section，每个班一张卡片（人数/均分/红黄绿），点击切到该班筛选；名单筛选行加班级 select
- **资源上传后端**（app.py 新增 4 个接口）：
  - `GET /api/teacher/resources?kind=` 列出（教师看自己的、学生看全部）
  - `POST /api/teacher/resources` 上传（multipart，kind=exam|tutorial，≤50MB，存到 `data/teacher_resources/`，metadata 写 `index.json`，写盘失败退化内存态）
  - `DELETE /api/teacher/resources/{rid}` 删除（仅自己的）
  - `GET /api/teacher/resources/{rid}/download` 下载（教师与学生均可）
- **资源上传前端**：
  - types.ts 加 `TeacherResource`；api/client.ts 加 `teacherResources` / `deleteTeacherResource` / `uploadTeacherResource` / `downloadTeacherResource`
  - 新建 `ResourceView.vue`：两个 tab（📄 历年期末真题 / 🎬 网课资源）+ 上传表单（选文件/课程/班级/说明）+ 列表（下载/删除）
  - 路由 `/teacher/resources`（教师）与 `/student/resources`（学生）
  - modules.ts：教师端「教学资源」分组加「历年真题」「网课资源」入口；学生端「我的成长」分组加「学习资源」入口
- **依赖**：FastAPI 处理 multipart 需要 `python-multipart`，已 `pip install python-multipart`
- **验证**：教师端 7 张班级卡片（全部 + 6 个班）；资源页两个 tab + 上传表单齐全；curl 上传 test.txt 返回 `ok:true, item.filename:"test.txt"`；列表显示已上传资源 + 下载/删除按钮
