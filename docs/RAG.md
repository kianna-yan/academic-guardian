# RAG：知识库检索是怎么做的

一句话：**把「问校规」从模型凭印象回答，改成从知识库原文里检索、带出处、可核对地回答。**

代码位置：

| 文件 | 作用 |
|---|---|
| `knowledge/*.md` | 语料（16 篇 / 88 个片段 / 约 6800 字），每篇带 front-matter（学校 / 文件 / 生效） |
| `engine/rag.py` | 分块、双通道检索、融合、重排、查询改写、向量缓存 |
| `engine/agent.py` → `call_rag()` | 把检索接进问答链路，并把检索过程写进轨迹 |
| `engine/media_memory.py` | 会话级材料记忆（图片 / 视频 / 语音） |
| `engine/tools.py` → `search_policy` | 模型自己决定检索时用的工具 |
| `tests/rag_eval.py` | 检索评测（Recall@1 / Recall@3 / MRR，含 ablation） |

## 1. 语料怎么组织

按「学校 + 文件」组织，一节一个片段：`## 章节标题` 切块，块内保留原文，块上挂
`school / doc / path`（如「《本科生学籍管理规定（整理稿）》 · 降级试读的条件」）。
超长小节按句子切，相邻块留 overlap，避免答案正好卡在切口。

引用展示的就是这个 `path`——用户看到的不是「某个 md 的某一行」，而是
「哪份文件、哪一条」。

## 2. 检索：两条通道 + 融合 + 重排

```
问题 → 查询改写 → ┬ BM25（关键词，字面命中）
                 └ 向量（智谱 embedding-3，语义相近）
                        ↓ RRF 融合（只看名次，两路分数量纲不同也能合）
                        ↓ 重排（标题命中 / 正文覆盖 / 同义扩展 / 学校匹配 / 短块惩罚）
                        ↓ 归一化成 0~1 相关度，低于阈值丢弃
                    Top-3 条款 + 出处 + 相关度 + 命中原因
```

为什么是两条通道：

- **BM25 强在字面**：「降级试读 25 学分」这种带专有名词和数字的问法，关键词命中就是准。
- **向量强在语义**：「挂了多少分会被劝退」和原文「退学警示」之间没有共同词，字面查不到，向量能。
- 只用其一都有明确的漏检场景，所以两路都跑，用 RRF 融合——RRF 只比较名次，不比较分数，
  绕开了「BM25 分数没有上限、余弦相似度 0~1」这种量纲不一致。

**查询改写**：把口语问法补上制度术语（「挂科」→ 不及格 / 补考 / 重修 / 推免 / 绩点排名），
用一张同义词表和「上一轮用户原话」提供上下文，解决「那保研呢」这种省略句。

**分词**：装了 jieba 就用 jieba + 学业领域词表（`学业预警 / 降级试读 / 缓考 / 推免 / 家校沟通`
等 60 多个词强制成词），切不了再退回字符 bigram —— 没装也能跑，只是排序弱一点，
`/api/kb/stats` 的 `segmenter` 字段会显示当前用的是哪条路。
这一项对指标影响最大：同一个知识库，bigram 时基线 Recall@1 只有 81.1%，
换词典分词后升到 94.6%（碎片词不再虚增覆盖率）。

**重排里的 key_hit**：按词的稀有度（idf）给覆盖率加权。普通覆盖率把「什么」「可以」
和「缓考」算成同等一票，问「什么情况可以申请缓考」时就会被「什么情况必须补考」抢走；
按 idf 加权后专有词一票顶白话词好几票。

**阈值**：相关度 < 0.25 的片段不进上下文。宁可不答，也不拿弱相关条款凑数——
编条款比说「没查到」严重得多。

**性能**：查询向量带缓存，同一问法第二次检索 8ms 左右；首次含一次 embedding 网络往返（约 0.4~0.5s）。

## 3. 回答里怎么用

- 交给模型的是编号条款（`[1] [2] [3]`）＋出处＋相关度，提示词要求「引用时标序号，只能引用这几条」。
- 前端每条引用可展开：出处、学校、相关度百分比、命中原因（标题命中 / 语义相近 / 同义扩展命中）、原文。
- 轨迹里有一条 RAG 面板：**改写前后的查询 → 走了哪条通道 → 多少候选 → 命中几条 → 每条多少分**。
  评委问「这条规定哪来的」，直接展开给他看。

## 4. 多模态材料的「记忆」

原来的问题：图片识别结果只拼在当轮提问里，下一轮追问就没了，模型只能回「我没看到图片」。

现在的做法（`engine/media_memory.py`）：

1. 每轮材料识别完成后，按账号把「识别出的文字 + 原图字节」存进会话记忆（最近 6 次，图片最多 4 张）。
2. 下一轮如果没带附件，但问法里出现「刚才那张图 / 上面 / 视频里」这类指代，
   自动把上轮的识别结果回灌给主模型。
3. 如果追问的是具体细节（第几行、多少分、叫什么），**把原图重新送一次视觉模型按新问题复核**，
   用图上的原文回答，而不是复述上一轮的概括。
4. 材料上的数字与系统数据不一致时，两个都写出来，并说明学情数据以系统为准。

## 5. 评测

```bash
python -m tests.rag_eval          # 表格
python -m tests.rag_eval --detail # 带每条命中明细
```

37 条人工标注问法，覆盖学籍、补考重修、考勤请假、申诉、奖助、推免、心理、办事、多校办法九类；
一条问法允许多个正确章节（同一件事常散在多份文件里），命中其一即算对。

| 配置 | Recall@1 | Recall@3 | MRR@3 | 平均耗时 |
|---|---|---|---|---|
| A 纯 BM25（基线） | 94.6% | 100% | 0.964 | <1 ms |
| B BM25 + 查询改写 | 86.5% | 100% | 0.928 | <1 ms |
| C 混合检索（线上） | **100%** | **100%** | **1.000** | 280 ms（首次）/ 8 ms（缓存） |

结论：

1. 加了**词典分词**（jieba + 学业领域词表，装不上就自动退回字符 bigram）之后，基线本身从 81.1% 提到 94.6%——
   原来「还能」「金吗」这种 bigram 碎片也算命中，覆盖率被灌水，术语有没有命中反而看不出来。
2. 混合检索把 Top-1 从 94.6% 拉到 100%，MRR 0.964 → 1.000，37 条全部 Top-1 命中。
3. B 行（只改写不加向量）低于 A：扩词会把少数问题带偏，说明**改写要靠语义通道才能兑现收益**，
   这正好用来解释「为什么不只做查询改写」。
4. 线上取 C。检索层对模型不可用是硬隔离的：向量接口挂了自动降级本地字符向量，
   评测里 `vector_mode` 会显示 remote / local，指标依然可复现。
